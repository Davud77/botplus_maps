# Карты, пользователи и публикации

## Роли в общей установке

| Действие | Наблюдатель | Редактор | Администратор |
| --- | --- | --- | --- |
| Смотреть внутренние карты и общий каталог данных | Да | Да | Да |
| Менять свой пароль | Да | Да | Да |
| Загружать и изменять данные общего каталога | Нет | Да | Да |
| Создавать карты | Нет | Да | Да |
| Изменять и публиковать свою карту | Нет | Да | Да |
| Изменять и публиковать чужую карту | Нет | Нет | Да |
| Создавать пользователей, назначать роли, отключать аккаунты | Нет | Нет | Да |
| Создавать базы данных | Нет | Нет | Да |

Это единое рабочее пространство с общим каталогом. Раздельные организации, группы, права на отдельные наборы и закрытые проекты ещё не реализованы. Наблюдатель видит внутренние карты и данные всей установки. Редакторы совместно управляют исходными наборами; владение ограничивает изменение конфигурации карты.

Сервер проверяет актуальные роль, состояние аккаунта и версию сеанса для каждого защищённого API-запроса. Отключение аккаунта и смена пароля отзывают прежние сеансы. При смене пароля текущий браузер получает новый сеанс. Последнего активного администратора нельзя отключить или понизить, включая одновременные запросы.

При обновлении старой установки существующий администратор сохраняется. Если в старой базе ещё не было роли администратора, её получает самый ранний аккаунт, остальные старые роли `user` становятся наблюдателями. Пароли и данные сохраняются. Переход выполняется один раз. Созданный мастером первого запуска администратор остаётся администратором.

## Работа с картой

1. На главной нажмите **Создать карту**, введите название и необязательное описание.
2. В редакторе выберите ортофотопланы и векторные слои, подложку, нужный масштаб и ракурс.
3. Нажмите **Сохранить карту**. Конфигурация хранится в PostgreSQL; после перезапуска она восстанавливается.
4. Одновременное сохранение из двух окон защищено номером версии. При конфликте обновите страницу, чтобы не перезаписать чужие изменения.

По умолчанию внешняя подложка отключена: отображаются ваши локальные слои. При необходимости выберите подложку в панели «Слои карты»; этот выбор обращается к внешнему поставщику тайлов.

Переход между картами очищает предыдущий выбор слоёв. Панорамы можно сохранять как внутренний слой общего каталога.

## Публичная ссылка

В редакторе откройте **Публикация** и опубликуйте сохранённую карту. Ссылка `/p/<случайный идентификатор>` открывается без входа и даёт только просмотр.

Публикуется копия названия, описания и конфигурации выбранных слоёв. Последующие правки черновика не появляются по ссылке до нажатия **Обновить публикацию**. Данные самих слоёв остаются живыми: изменение или удаление исходного набора влияет на публикацию. Это не архивная версия геоданных. Векторные объекты публикуются с атрибутами; проверьте их содержимое перед публикацией. Стили публичного вектора пока используются стандартные.

Общедоступные API проверяют принадлежность каждого растрового или векторного тайла опубликованной конфигурации. Они не открывают API каталога, управления пользователями и скачивания исходников. Отключение публикации отзывает ссылку; повторное включение создаёт новую. Публичные ответы отправляются с `Cache-Control: no-store`; уже скачанные посетителем данные отозвать невозможно.

Публичные панорамы пока не реализованы. Перед публикацией отключите слой панорам и сохраните карту: сервер отклоняет публикацию общего каталога панорам целиком.

На локальном профиле приложение доступно только на компьютере владельца. Для внешних посетителей нужен ваш сетевой адрес, HTTPS и соответствующие настройки установки; ссылка `localhost` с другого компьютера недоступна.

## Закрытое хранилище

Новые орто-бакеты не получают анонимную политику чтения. При старте удаляется точная публичная политика, которую автоматически создавали прежние версии BotPlus. TiTiler получает данные через подписанный `s3://` доступ. Если у вас настроены собственные политики, внешние ссылки MinIO или reverse proxy, проверьте их отдельно: пользовательские политики автоматически не переписываются.

При обновлении старого Compose-профиля перезапустите также TiTiler: анонимный доступ `AWS_NO_SIGN_REQUEST=YES` заменён подписанным чтением. Ранее опубликованные прямые S3-ссылки на бакет с автоматической политикой перестанут работать. Для совместного доступа используйте публикацию карты через приложение.

## Каталоги карт и оформление

В «Данные и настройки» доступны разделы «Системы координат», «Подложки» и «Оформление».
Администратор добавляет общие CRS (EPSG, WKT, PROJ) и XYZ/TMS подложки, выбирает значения по умолчанию для новых карт.
По умолчанию новые карты используют Google Maps; для автономной установки выбирайте «Без подложки» или локальный сервер тайлов.
Внешние подложки обращаются к провайдеру напрямую из браузера; права и условия использования источника определяет его провайдер.
Кастомные определения CRS проверяются GDAL/PROJ; внешние файлы и сетки в определениях не поддерживаются.
Выбранная СК используется для пересчёта координат центра; отображение веб-карты остаётся в EPSG:3857. Это не изменение исходной СК геоданных.
Тема light/dark сохраняется отдельно для каждого аккаунта и кэшируется в браузере для страницы входа.

Каталоги «Векторные слои» и «Ортофотопланы» добавляют данные кнопкой «+».
Панель «Слои на карте» управляет видимостью, удалением из карты, порядком и прозрачностью.
Векторные слои имеют настройки цвета, толщины, заливки и радиуса точек; кнопка «Стиль источника» возвращает исходное оформление.
Порядок задаётся сверху вниз, верхний слой перекрывает нижний. Прозрачность и порядок применяются через отдельные Leaflet panes без повторной загрузки тайлов.
Векторы загружаются отдельными MVT источниками, чтобы растры и векторы могли чередоваться в порядке карты; полная геометрия в браузер не передаётся.
Настройки сохраняются кнопкой «Сохранить карту», затем переносятся в снимок кнопкой обновления публикации.
Снимок содержит определение подложки и оформление слоёв; имена внутренних баз и схем не включаются в публичный JSON.
Невидимые опубликованные слои остаются частью снимка и доступны через scoped tile API: видимость — оформление, а не отдельное ограничение доступа. Чтобы исключить слой из публикации, удалите его из карты, сохраните и обновите публикацию.

API: GET `/api/settings/map`, POST `/api/settings/coordinate-systems`, POST `/api/settings/basemaps`,
PATCH `/api/settings/map/defaults`, PATCH `/api/account/preferences`, GET `/api/settings/coordinates`.
Изменения каталогов доступны только администраторам, собственная тема — всем ролям.
