# Импорт, каталог и задания

В профиле разделены **Импорт** и **Задания**. Старые адреса `/upload` и
`/uploadortho` перенаправляют в единый импорт с выбранным типом данных.

## Сохранение оригиналов

- Первая вкладка — загрузка файла с компьютера. Файлы передаются последовательно;
  страница должна оставаться открытой. GeoTIFF сохраняется в `IMPORT_STAGING_DIR`,
  JPEG/WebP — в `MEDIA_ROOT/panoramas`. При NAS-развёртывании обе папки находятся на NAS.
- Вкладка «С диска / NAS» показывает подключённые `LOCAL_SOURCE_ROOTS` и позволяет
  выбрать файл или папку без ввода пути. Ортофотопланы копируются worker-процессом
  в `media/orthophotos/originals`; панорамы NAS подключаются по ссылке.
- Импорт GeoTIFF читает метаданные и регистрирует исходник. Конвертация и построение
  пирамид автоматически не запускаются. Готовый COG используется непосредственно.
- Для большой партии панорам worker общей очереди последовательно читает EXIF
  и заголовки изображений. Это фоновая регистрация, без изменения пикселей,
  преобразования изображений или копирования NAS-файлов. По умолчанию включён фильтр 360°.
  Ход регистрации и повтор без дубликатов доступны в «Заданиях».
- Массовый импорт не требует передачи содержимого NAS-файлов через браузер.

## Проекции и обработка

Если проекция файла отсутствует в каталоге, создаётся `unknown_N`. Встроенное
определение сохраняется, если оно есть. При отсутствии определения координаты не
угадываются и слой нельзя расположить на карте. Администратор может добавить
определение в разделе «Проекции», сохраняя имя `unknown_N`. Это не переписывает исходник.

Подготовка COG и для карты запускается кнопками в каталоге ортофотопланов.
Импорт, смена проекции и подготовка используют общую очередь. Обработка требует свободного места на NAS; исходник сохраняется.

## Каталог панорам

Список загружается страницами (50 записей, API до 100), маркеры карты — по текущему
охвату с кластеризацией и лимитом. Доступны поиск, логические папки, теги, выбор до
500 объектов и пакетные операции. Папки хранятся в PostgreSQL: перемещение не меняет
физический путь NAS. Удаление переносит записи в корзину; восстановление доступно
в том же интерфейсе. Корзина не удаляет физические файлы. Удалять можно только пустую
логическую папку, включая отсутствие объектов в корзине.

## Системные журналы

Вкладка «Задания» содержит журналы операций и, для администратора, ограниченный
снимок журналов app, worker, media-worker, db и titiler. Снимок обновляется отдельно
от API: Docker socket приложению не передаётся. Пароли, DSN и токены маскируются;
снимок ограничен последними 30 минутами и 150 строками на сервис.

Для серверного размещения в `/opt/botplus/app` установите шаблоны из
`deploy/systemd/botplus-service-logs.*` в `/etc/systemd/system/`, затем:

```sh
systemctl daemon-reload
systemctl enable --now botplus-service-logs.timer
systemctl start botplus-service-logs.service
```

Путь снимка `/srv/botplus/work/logs/services.json` должен соответствовать NAS-папке
`/app/data/logs/services.json` приложения. Сборщик читает Docker от root и до записи
сбрасывает права до UID/GID 10001. Не публикуйте эти журналы в открытый доступ.

При обновлении действующего сервера запускайте только `app` и `media-worker` с
`--no-deps`: не пересоздавайте `worker`, пока выполняется ранее запущенный COG.
Перед обновлением сделайте резервную копию PostgreSQL и конфигурации Compose.
Скрипт `scripts/seed_media_sources.py` связывает прежний проверенный манифест с
каталогом для дедупликации; он не копирует файлы и не импортирует новые записи.


## Общая очередь

Импорт из профиля сохраняет переданные байты и создаёт задание.
Регистрация, COG, смена проекции, превью, подготовка для карты и импорт панорам
выполняются в общей очереди FIFO в фоне. При выборе папки ОФП создаётся одно
задание: worker последовательно обходит GeoTIFF и показывает общий прогресс.
Оригиналы ортофотопланов из NAS копируются в `media/orthophotos/originals`.
Готовые задания скрываются кнопкой «Готово»; журнал сохраняется.
