# Актуальный режим импорта

По умолчанию `import-raster` только регистрирует оригинал. Для явной подготовки отдельного COG используйте `--prepare`; только с ним действуют `--wait` и `--source-crs-id`. Веб-загрузка также не создаёт задания обработки. Актуальные формы и каталог описаны в [IMPORT_CATALOG.md](IMPORT_CATALOG.md). Ниже технические сведения об инспекции и очереди подготовки.

# Локальный импорт и очередь заданий

Реализованы две независимые операции: **inspect-raster** проверяет файл локально без приложения, а **import-raster --prepare** отправляет серверу ссылку на подключённый файл и ставит явное задание подготовки в PostgreSQL. Готовый COG подключается без копирования; обычный GeoTIFF готовится отдельным worker в новый COG, сохраняя оригинал.

## Запуск в контейнере

Docker с работающим daemon; первый build получает базовый образ и пакеты из Интернета. После сборки проверку можно выполнять без сети. Файлы на NAS сначала доступны на хосте, затем монтируются в контейнер.

```sh
docker build -f Dockerfile.tools -t botplus-tools:local .
docker run --rm --network none \
  --mount type=bind,src=/srv/geodata,dst=/sources,readonly \
  botplus-tools:local inspect-raster /sources/ortho.tif > ortho-inspection.json
```

Замените `/srv/geodata` на существующую папку с данными. UID контейнера — 10001; администратор должен дать ему право чтения файла/прохода по папкам. Контейнер не должен получать root или writable-доступ ко всему диску ради чтения.

## Запуск в Python

Нужны GDAL и соответствующие ему Python bindings. Запускается из корня репозитория:

```sh
python -m server.cli inspect-raster /srv/geodata/ortho.tif > ortho-inspection.json
python -m server.cli inspect-raster /srv/geodata/ortho.tif --source-crs EPSG:32638
python -m server.cli inspect-raster /srv/geodata/ortho.tif --crs-file /srv/crs/local.prj
```

`--source-crs` / `--crs-file` описывает **исходные** координаты; это не команда перепроецирования. Существующий CRS override нужно задавать только если встроенное определение известно как отсутствующее/ошибочное. Оригинал не меняется; override фиксируется в отчёте. При отсутствии CRS команда не угадывает её по числам.

Поддержка локальной CRS означает возможность разобрать определение и найти корректную локально доступную операцию в WGS84. Она не означает, что достаточно произвольного названия МСК: может понадобиться datum, зона, параметры или grid. Сетевое скачивание PROJ grids выключено; приблизительная ballpark-операция запрещена.

## Результат

JSON содержит размер файла, размеры raster, полный WKT2, native bounds, уплотнённый WGS84 footprint/bbox, тип и block size каналов, список overviews и metadata hint COG. Для rotation используются все четыре affine-угла. GCP/RPC-only GeoTIFF и пересечение antimeridian пока отклоняются с явной ошибкой — им нужна отдельная подготовка.

Проверка читает заголовки, геопривязку и metadata, **не запускает** statistics/histogram/checksum или чтение всех пикселей. OS/GDAL могут читать вспомогательные metadata и служебные TIFF-структуры; время не является гарантированно константным для любого TIFF. На сотнях GB нет обязательного буфера такого же размера в RAM.

`validation=metadata_only` и `publication_ready=false`: это не полная structural COG validation и не проверка каждого блока. `mtime_ns/size_bytes` — fingerprint для обнаружения изменений, не криптографическая checksum. Источник не должен меняться во время проверки; read-only mount не запрещает запись в файл со стороны других программ на хосте.

При успехе exit code 0 и JSON в stdout. При ошибке exit code 2, объяснение в stderr. Отчёт содержит локальный путь — не выкладывайте его публично, если структура ваших каталогов закрыта.

## Подключение папки с данными

Локальный Compose использует источник `local`: папка `data/sources` проекта смонтирована read-only в app, worker и TiTiler по одинаковому пути `/sources/local`. `configure_local.py` создаёт пустую папку. Большие архивы копировать туда не требуется: задайте в `.env.local` переменную `LOCAL_SOURCE_DIR=/srv/geodata` (или путь к уже подключённому NAS), затем пересоздайте сервисы:

```sh
docker compose --env-file .env.local -f compose.local.yml up --build -d
```

Приложению и renderer нужен доступ на чтение, а worker — отдельный writable рабочий том для staging и COG. UID app/worker — 10001. Не выдавайте write-доступ к архиву. TiTiler не публикуется на хост.

Для своего deployment задайте `LOCAL_SOURCE_ROOTS='{"archive":"/sources/archive"}'` и смонтируйте одну и ту же папку в app, worker и TiTiler по одному пути read-only. `IMPORT_STAGING_DIR` и `IMPORT_PRODUCTS_DIR` должны быть постоянными, общими для app/worker; TiTiler читает их по тем же путям read-only. Пути клиента не являются путями сервера. API принимает только root ID и относительный `.tif/.tiff` key; абсолютные пути, `..` и симлинки за пределы root отклоняются.

## CLI без передачи файла

CLI использует HTTP API и обычную учётную запись редактора/администратора; доступ к PostgreSQL с клиентской машины не нужен. Команды не читают пиксели локального raster и не отправляют содержимое файла:

```sh
python -m server.cli sources --server http://localhost:5580 --username operator
python -m server.cli import-raster local survey/ready.tif --server http://localhost:5580 --username operator --wait
python -m server.cli jobs --server http://localhost:5580 --username operator
python -m server.cli job JOB_UUID --server http://localhost:5580 --username operator
python -m server.cli job JOB_UUID --action cancel --server http://localhost:5580 --username operator
python -m server.cli job JOB_UUID --action retry --server http://localhost:5580 --username operator
```

Пароль вводится через скрытый prompt. Для скриптов допускается `BOTPLUS_PASSWORD` из защищённого окружения; не передавайте пароль аргументом команды и не сохраняйте его в Git. Dockerfile.tools включает HTTP-клиент: внутри compose-сети можно использовать `--server http://app:5000`; вне контейнера — адрес установки, для удалённого доступа HTTPS.

`--idempotency-key` задаёт ключ запроса; без него вычисляется ключ версии источника из root/key, stat fingerprint и рецепта. Повтор одной версии тем же пользователем возвращает то же задание. Регистрация одного источника разными пользователями сериализуется: результат с одинаковой сигнатурой один. Возвращаемые JSON не содержат пароли, абсолютные пути источников и signing secrets.

`--source-crs-id EPSG:32638` или `custom:UUID` — явное переопределение **исходной** привязки из каталога установки. При таком override всегда готовится отдельный COG, даже если исходник уже COG. Это отличается от выбора СК показываемых координат в настройках слоя.

## Веб и worker

«Данные и настройки → Импорт» сохраняет исходники без подготовки. «Задания» содержит очередь явной обработки, регистрацию панорам и журналы. Старые веб-адреса перенаправляют в единый импорт. Подробности: [IMPORT_CATALOG.md](IMPORT_CATALOG.md).

Worker запускается отдельным сервисом `worker`, не внутри Flask/Gunicorn. Локальный Compose ограничивает его 1 GiB RAM и двумя CPU (`IMPORT_WORKER_MEMORY`, `IMPORT_WORKER_CPUS`); эти лимиты настраиваются под данные и сервер. Состояния: queued/running/succeeded/failed/cancelled. Есть прогресс, последние 100 событий журнала, отмена и повтор. Редактор видит собственные задания, администратор — все; наблюдатель не создаёт и не читает задания. Каталог растров пока общий для аутентифицированного пространства, как описано в WORKSPACE.md.

Аренда worker — 90 секунд, продление каждые 5 секунд. `FOR UPDATE SKIP LOCKED` позволяет независимые worker без двойного захвата. После аварии аренда истекает, задание повторяется, максимум три попытки; далее нужен явный повтор. Lease token проверяется перед регистрацией результата: опоздавший процесс не может опубликовать слой. Штатная остановка возвращает задание в очередь. Отмена кооперативная: во время GDAL она проверяется callback и heartbeat; заблокированное чтение NAS может потребовать завершения процесса.

Результат появляется в каталоге ортофотопланов. Добавление в карту и публикация выполняются отдельно. Для локального слоя старые in-place операции обработки заблокированы; исходник и производную нельзя перепроецировать через legacy API. Удаление регистрации убирает слой из каталога, сохраняя файлы. Успешные/ошибочные upload originals и производные остаются на диске: автоматическая очистка и квоты ещё не реализованы. После SIGKILL могут оставаться незавершённые attempt directories — не удаляйте рабочие файлы активных заданий.

## Границы гарантий

Подключение COG использует metadata layout hint и наличие overviews для крупных raster; это не структурная проверка всех TIFF-блоков. Проверка больших реальных архивов и производительности ещё предстоит. Подготовка COG ограничивает GDAL cache до 128 MiB и число потоков до двух; preflight свободного места консервативный, реальная потребность зависит от файла. Нет гарантии общего RSS=128 MiB: драйверы и компрессоры используют дополнительную память.

Stat fingerprint включает size/mtime/ctime/device/inode и проверяется при постановке, регистрации и перед новым доступом к локальному слою. Изменение исходника или производной приводит к отказу, а не незаметной подмене опубликованной карты. Это не криптографическая проверка и не защита от внешнего writer, меняющего файл одновременно с чтением: храните источники неизменяемыми, используйте права доступа/снимки файловой системы. Перенос на другой диск или восстановление backup может потребовать повторного импорта из-за смены inode/device. Для backup нужны PostgreSQL, исходники и постоянный рабочий том; не только image контейнера.

Следующие этапы: resumable/multipart upload, reconciliation/GC производных, квоты, batch manifests, фоновые импорты панорам/векторов и права на отдельные наборы.
