# ADR 0003: обычные файлы на NAS, обработка на сервере

Принято 22.10.2026. Уточняет ADR 0001 для текущей реализации.

- Исходники, COG, фотографии и панорамы хранятся в обычных каталогах владельца.
- PostgreSQL/PostGIS хранит пользователей, карты, каталог, задания и векторы на серверном диске.
- API, worker и TiTiler работают на вычислительном сервере; MinIO/S3 не требуется.
- API/worker используют одинаковые контейнерные пути; TiTiler получает те же данные только для чтения. Браузер получает авторизованные ответы приложения.
- Каталог читается из PostgreSQL, а не обходом NAS. Файлы новых панорам получают UUID и два уровня подкаталогов; совпадающие исходные имена не перезаписывают друг друга.
- Запись идёт ограниченными блоками во временный файл рядом с результатом. `fsync`, атомарная hard-link публикация без перезаписи и fsync каталога требуют POSIX-совместимой файловой системы с hard links. Для NAS проверяется фактическое поведение NFS.
- Изменять или удалять зарегистрированные файлы вне приложения нельзя. Исходники подключены только для чтения; удаления управляемых файлов не затрагивают исходный каталог.

Файловая система и PostgreSQL не образуют общую транзакцию. При ошибке записи каталога панорамы выполняется компенсационное удаление нового файла; при аварийном завершении между операциями возможны сироты. Outbox/reconciliation/GC, возобновление загрузок, очередь подготовки панорам и измерения на миллионах объектов остаются следующими этапами. Хранилище само по себе не обеспечивает целевой масштаб.

Миграция — копирование объектов через прежний S3 API с SHA-256 проверкой. Исходный MinIO и его тома сохраняются до проверки. Не копировать внутренние `.minio.sys`/shards как пользовательские файлы. Подробности: [инструкция](../FILESYSTEM_STORAGE.md).
